# Lab 2 · Agile planning and defect tracking

Open [board.html](board.html) to switch between the Kanban board, Sprint 1 and the bug register. Use each card's status control to move it. This standalone board saves edits in the browser when local file storage is available. The PDFs capture the initial planning and defect records.

| Submission | What it records |
|---|---|
| [Kanban](Kanban.pdf) | Seven stories, two planned sprints and four workflow states |
| [Scrum](Scrum.pdf) | Sprint goal, three acceptance scenarios, 13 estimated points and a five-day ideal burndown |
| [Bug report](BugReport.pdf) | Five reproduced defects in the Lab 5 baseline, expected results and regression coverage |

The story IDs use the [main requirements specification](../1-RE/RE_Document.md). [Stories](stories.csv) and [bugs](bugs.csv) can be imported into Jira. Map Issue Type, Summary, Description, Priority and Labels, then place ST-01, ST-02 and ST-06 in Sprint 1. The PDFs are local planning records. If the marking sheet requires Jira screenshots, capture your own board, sprint report and bug list after import.
